## Canonical end-to-end synthetic transaction

1. Existing immutable migrations 001–013 are applied to a random private PostgreSQL 17 Compose fixture (no exposed host ports). Existing `issuer_origin_uat.sql` issues **four fake A/B grants for one device** over sequential and concurrent transactions. Its per-device generation/grantRevision is 4:4 and all four outboxes start `pending`.
2. New `issuer_publisher_uat.sql` extends **scratch tables only** (not production migration). `lr_uat_claim_signing(worker,token)` cancels superseded `pending` generations before signing. Two concurrent workers attempt `FOR UPDATE ... SKIP LOCKED` on the latest outbox and device floor. Exactly one gets generation 4; the other gets no row. Claim has `claim_seq` increment and 30-second timeout.
3. New `synthetic-outbox-lease-publisher.mjs` is a **standalone private test signer**. The Node CLI requires `--synthetic-only` plus `LR_RC50_UAT_ONLY=1`; input is a fabricated database claim, never a real grant. It generates an ephemeral Ed25519 keypair in its own RAM, validates explicit fake namespace, fields, claim sequence and <=30-second signed lease, signs a domain-separated canonical packet, self-verifies the signature and returns the signed packet, SHA-256 packet digest and public-key fingerprint. It does **not** emit a private key or an OS-action authorization.
4. `lr_uat_finalize_signing` requires exact live claim owner token + sequence, valid unexpired grant/connection, matching enrolled device public-key digest, current issuer pin and **same generation/grantRevision as current device floor**, signature syntax and lease expiry <=30sec and <=original grant. It marks one immutable `signed` row. A timed-out signer cannot publish an old claim, even if the stale response arrives after another worker reclaim.
5. `lr_uat_ack_signed_lease` accepts a **synthetic** ACK with matching signed digest, grant ID, enrolled device public-key digest and nonce hash. It denies revoked enrollment, closed grant, expired lease or changed device floor. It inserts into `lr_uat_lease_delivery_ack` with unique request/nonce; exact repeat ACK returns `ACK_DUPLICATE_NOOP`, different nonce/digest is refused.

## Strong limitations — do not promote

- The **owner approval remains fabricated** in scratch DB. Production Local Wall session, CSRF, B-code approval event, real device-channel ACK and validated PostgreSQL provenance are not wired to this fixture. The current real Local Wall path was audited earlier at commit `022d00e` but is untouched.
- The issuer key is generated anew by the fixture CLI and a test runner populates the scratch `lr_uat_issuer_pin`. This is **not secure key custody, rotation or a production trust anchor**. A real issuer cannot let a caller reset its trusted key pin.
- **PostgreSQL does not cryptographically verify Ed25519**, and `lr_uat_finalize_signing` cannot prove the submitted signature was generated by a protected signer. Cryptographic validation is tested in Node; production requires a mutually authenticated signed-publisher service and exact payload verification before state transitions.
- The **device ACK is fabricated** and PostgreSQL checks only IDs, hash syntax, digest and state, not a real device private-key signature or device possession. A production device ACK must sign a challenge tied to receipt, lease/issuer fingerprint, generation, claim/nonce and retained grant high-watermark; the receiver must verify it.
- Generation floor serialization is local to **one scratch PostgreSQL instance**. No cross-host global writer epoch, authenticated writer fencing, split-brain recovery, durable signer dispatch retries, monotonic safe clock or offline revocation latency is proven.
- No production migrations, roles, Operator, Agent, Local Wall, Fleet, PTY, Real Remote, SCP, Paddle/billing, OAuth or user files are changed. **Global authority and production cutover remain `NOT_READY`.**
