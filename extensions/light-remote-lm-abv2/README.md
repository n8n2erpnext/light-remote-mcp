# Light Remote Memory v0.4.3

This is the single current extension source for local Windows/macOS/Linux Wall or the explicitly paired NetBird Lab Wall. The older0.2 and0.3 folders/ZIP remain historical, not a second active implementation. No Owner browser profile is installed or changed automatically.

1. Download the exact-source `light-remote-memory-extension-<commit>` Actions artifact, extract the ZIP, and load the `light-remote-memory` folder in a disposable Chrome profile first.
2. Open the extension, enter your Wall address and select **Pair this Wall**. In the setup tab, select **Allow and pair** and accept the Chrome request for your selected Wall. If prompted to sign in, select **Open Wall**, sign in there and return to the setup tab. Wait for **Paired with…**. Pairing binds the account and device at the exact selected address. Enable Long Memory in that Wall before importing.
3. In a ChatGPT or Claude conversation, open the extension and Capture. Only loaded DOM user/assistant text is read after your click. Review/redact in the popup, then Review in my Wall. Choose your work, opt in and manually Save in the existing Owner/CSRF/Home-checked Wall. A nonempty Wall draft is preserved. The extension does not choose a scope, change consent or click Save.
4. To restore, open the paired Wall and select the intended work. In the extension choose recent checkpoints, saved full context or auto-captured browser context, then select **Load**. Readback rechecks the account, device, scope and data integrity. Review or redact the returned text.
5. Open the destination ChatGPT/Claude chat yourself, reopen the extension and Insert. It only stages into a uniquely identified empty composer. An existing draft remains unchanged; Copy context is the alternative. It never submits or sends a message.

Capture checks each UTF-8 segment and the final review by SHA-256. It reads user bubbles and assistant responses from the loaded conversation, including the newer ChatGPT search-unit layout and older role-marked turns. Hidden blocks, controls and tertiary status text are filtered. The 512 KiB maximum fails without truncating. Loaded DOM coverage excludes unloaded messages, attachments, images and hidden reasoning. A changed conversation or digest aborts capture. The prepared transcript remains historical context for review.

## Auto-capture a conversation

Open the chat you want to follow. In **Auto-capture this chat**, choose a work stored on your paired Wall, then select **Start auto-capture**. This requires an updated Wall. The extension checks about once a minute while the chat tab and the signed-in Wall tab stay open. It waits when it detects a reply in progress. Changed loaded text goes directly to the selected Wall for that work. Choose **Stop auto-capture** to end the watch. Switching that tab to another conversation, closing it, or restarting Chrome ends the watch. Start it explicitly in each chat you want to follow.

Wall keeps the latest successful loaded snapshot per captured chat, up to 512 KiB each. View the latest snapshot for a work under **Browser context**. This can include the contents of loaded messages, so enable it only for chats you want to save automatically. Agent checkpoints remain available under their existing actions. MCP can read the separately marked browser history through `scope_browser_context` on an updated Agent.

Pending manual imports/restores use trusted-context-only Chrome storage.session and a 10-minute limit. Successful staging removes its pending copy and tab closure removes its import. An auto-capture watch keeps routing and receipt metadata in session storage. It saves text only to the paired Wall using the existing optional Wall permission. The extension uses the Chrome action's activeTab grant for supported chats. Google Sans is packaged from the app asset with its OFL license.

Verification covers portable VM tests, synthetic conversation DOM, and an installed MV3 extension in an isolated browser profile with access seeded to a test Wall. The fixture covers sign-in, an already open Wall, and pairing that completes after the action popup closes. Chrome's native permission prompt and real account acceptance can be checked in your own test profile. Keep only one version of the extension enabled during testing.

Chrome API references. [activeTab](https://developer.chrome.com/docs/extensions/develop/concepts/activeTab), [optional permissions](https://developer.chrome.com/docs/extensions/reference/api/permissions), [session storage](https://developer.chrome.com/docs/extensions/reference/api/storage).
