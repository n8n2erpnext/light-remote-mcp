# Gold M5 — Supervisor restart reconciliation and crash-safe operation journal

**Date:** 2026-10-21. **Baseline:** [real LXD separate Supervisor surviving Agent restart](./RDC_GOLD_M5_INDEPENDENT_PROCESS_SUPERVISOR_20261021.md). **Master:** [Multi-Agent / Job Scheduler Plan](./RDC_GOLD_MULTI_AGENT_JOB_SCHEDULER_MASTER_PLAN_20261021.md).

## Decision and accurate guarantee
Do NOT describe an in-memory NativeProcessRegistry as durable across its **own** process restart. Its `close()` sends stop and a systemd unit configured with `KillMode=control-group` terminates its descendants. A Supervisor crash may lose the exit receipt. The safe intermediate contract is **journaled reconciliation**: no fabricated `running`/success, no double execution on repeated `operationId`, terminal results survived if fsynced. A true executable job surviving Supervisor exit/reboot requires separate per-job cgroups/process guardians and durable stdout/exit leases, later M5 hardening.

## Source implementation (Gold opt-in)
- New `lib/supervisor-job-journal.mjs` writes **only** ownership identity, hashed per-owner operation key, fingerprint, process id/pid, timestamps and terminal status; **never command scripts, process environment, network URLs, stdout, tokens or secrets**. Directory must be **absolute, owner-owned mode 0700**, journal file 0600; atomic temp write, file fsync, rename and directory fsync; corrupt/insecure journals fail closed on Supervisor startup.
- `device-agent/process-supervisor.mjs` accepts optional `LIGHT_REMOTE_PROCESS_SUPERVISOR_JOURNAL_DIR`. It writes a reservation **before command spawn**, then attaches processId and status to the same record, fsyncs terminal exit on process-finished event. Opted-in calls without a valid `operationId` reject rather than launching an untracked process. Capacity capped, no broad JSON snapshot fallback in place of canonical PG job tables. This is strictly *local execution evidence*, not a replacement for future Operator PostgreSQL job/work-lease accounting.
- After Supervisor restart, previously `reserved`/`running` records become **`unknown`** with `unknownReason=supervisor_restarted_before_terminal_receipt`; finished/stopped/timeout/error receipts remain terminal. Unknown handles appear in owner-scoped `list`/Local Wall with `resultOrigin=supervisor_journal` and `outputAvailable=false`. They are **not** displayed as running. `output`, `input`, `stop` on detached unknown handles respond `409 prior_operation_status_unknown`; finished-but-reloaded output responds `409 process_output_unavailable_after_supervisor_restart` (stdout ring was in memory and cannot be reconstructed).
- Reusing the same authenticated owner+Agent+session `operationId` after restart cannot spawn a new command: `409 prior_operation_status_unknown`. Reusing same ID with different script/params is `409 operation_id_conflict`. A previously finished operation must likewise not re-run. This avoids a false exactly-once claim while protecting against duplicate external effects. Genuine retry of a new user task uses a **different** operationId and explicit user decision.
- New `selftest-gold-m5-supervisor-restart-journal.mjs`: starts a real bounded shell job, crashes Supervisor with SIGKILL and cleans the fixture process group, restarts Supervisor, verifies same processId appears **UNKNOWN** and duplicate retry/output/stop cannot execute; tests foreign Agent isolation and terminal receipt from another completed job survived a subsequent restart. Checks journal file mode 0600 and that script contents are absent.
- Existing client source remains backward-compatible: without journal env, behavior is identical to [first Supervisor slice](./RDC_GOLD_M5_INDEPENDENT_PROCESS_SUPERVISOR_20261021.md). The journal is designed for independent Linux Gold only; no Windows/macOS native client update or production flag.

## Safety and next phase
- Journaling UNKNOWN does **not** restart processes. For Supervisor restart when process is running, systemd control-group shutdown is expected to stop the process, but **the state may still be UNKNOWN** and requires confirmation rather than automatic relaunch. For abrupt parent crash outside systemd, old process could be alive; prohibit auto-retry until reconciled.
- A durable service across reboot requires persistent per-job OS scopes or workers, independently captured process exit and output, server-side PG coordinator + Redis ephemeral queue, and fencing to avoid old/new dual execution. Continue owner agent Stop / Team policies; no cross-account Team execution.
- Rollout isolated Gold UAT only: create an owner-only **persistent private** directory at `/var/lib/light-remote-gold-uat/supervisor-journal`, inject new journal env **only** into `light-remote-gold-process-supervisor.service`, and restart service under an explicit empty-job gate. Do not change Operator/Plugin/Wall permissions or production.
