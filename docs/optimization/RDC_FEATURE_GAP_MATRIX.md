## Most important causality distinction
**Hypothesis:** RDC may appear smoother in everyday tasks because fewer execution hops and task-oriented tool schemas produce fewer ambiguous tool arguments and state transitions. **Not demonstrated:** that OpenAI's private pre-dispatch safety classifier prefers RDC, or that changing tool descriptions can eliminate an OpenAI refusal. Evidence necessary: same benign intent + same authorized host/context + public metadata + whether device job exists; compare success/failure per layer over enough samples. Preserve all policy checks and do not recast sensitive commands as benign.

## G1 triage order after owner review
1. `requiredCapabilities` source of truth and explicit Docker/LXD read admission, including Fleet node vs authorized device distinction.
2. Tool result/error taxonomy with correlation ID and phase; never return `no permission` for a platform pre-dispatch denial.
3. MCP metadata/read-only annotations and client-agent tool choice ambiguity; no automatic dangerous tool execution.
4. Narrow retry on truly idempotent reads, not mutation auto-replay.
5. Record unsupported operations as NOT TESTED/BLOCKED, not FAIL of a different layer.

## Deliberate non-goals
No extra output buffer, general purpose Office support, full refactor into RDC architecture, REST/Supabase migration, removal of A/B, fake capability declaration, lowering OAuth scopes, bypass through PTY, or new JSON/SQLite persistence.
