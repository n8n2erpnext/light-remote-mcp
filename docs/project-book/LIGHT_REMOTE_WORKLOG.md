## 2026-10-30 — A/B V2 approval TTL decision: 5 minutes; legacy V1 unchanged
Before proceeding with P2-I1/I2 implementation, checked `operator-host/device-pairing-registry.mjs`: real legacy A code defaults to `DEFAULT_PAIRING_CODE_TTL_MS = 3 * 60 * 1000` and currently allows configured bounds of 30 seconds to 10 minutes. Owner considered 3 vs 5 minutes for the *new* Agent-initiated V2. Chosen product design is **300 seconds (5 minutes) fixed for V2 pending approval only**, calculated by server from exact request creation. The six-character immutable device Short ID remains visible indefinitely, the five-character temporary A suffix and independently issued B expire with the same pending request, with no timeout extension from polling/page reload/failed entry. One-time use, hard approval deadline, exact device/actor/request binding, rate limits, revocation and 24-hour approved A/B lease are mandatory. Legacy V1 TTL remains three minutes for client compatibility. This is a design/documentation decision; V2 protocol and timeout are NOT yet deployed or wired to live runtime.

## 2026-10-30 — A/B V2 Refresh/Recovery architecture retained from V1
Owner flagged that legacy Wall **Refresh A code** is an essential self-recovery mechanism when an Agent cannot find/consume the code, client time appears inconsistent or the connection is interrupted.
